# 「义项与用法」(use.us) 补写规范（给生成代理看）

App：德语背单词 PWA，用户是在德国读硕士、找 IT 工作的中国学生（A2–B1，目标 B2/C1）。很多词在详情里要显示「义项与用法」（仿红宝书：意思 → 句型 → 例句），有 2 个以上用法的词还会出「用法匹配题」：给出句型或例句，让用户选对应的中文意思。所以每条用法的中文意思必须彼此分得清。

## 输入
骨架 `wiktionary/gen/usNN.todo.json`：一个数组，每条是词库里已有的一个词：
`id`、`lemma`、`lv`、`pos`、`art`（名词）、`zh`（现有中文释义）、`gov`（介词/格支配，可能没有）、`senses`（现有义项，可能没有）、`ex`（现有例句）、`col`（现有搭配）。这些只是参考，**不要改它们**。

## 输出
`data/usage_us/usNN.json`：一个 JSON 对象 `{词 id: [用法, …]}`，UTF-8。
**只收真正有 2 个以上明显不同、常用的意思或固定用法的词**（不同义项、不同介词搭配、及物/反身/不及物的区别、固定短语）。只有一个用法、或几个中文释义只是同义词（如「美丽的；漂亮的」）的词，**不要写进输出**——预计大约一半的词会被跳过，这是正常的。

每个词 2–4 条，每条：`{"p": 句型, "zh": 中文意思, "ex": 德语例句, "exz": 例句翻译}`
- `p`（可选）：固定句型或搭配。格写成 `+ Dat.` / `+ Akk.` / `+ Gen.`，如 `"sich an + Akk. gewöhnen"`、`"Anspruch auf + Akk."`、`"in Anspruch nehmen"`、`"jmdm. etw. vorschlagen"`。只是一个意思、没有特别句型时省略 `p`。
- `zh`：这条的中文意思，2–10 字，同一个词的各条不能重复或近义到分不清。
- `ex`：一个自然、地道的完整德语例句，8–16 个词，**必须包含这个词**（可以是变化形式）和这条的句型；大写开头，句号（或问号/感叹号）结尾。贴近用户生活：工作、IT、大学、办事、新闻、日常。每条例句不同，也不要照抄骨架里的 `ex`。
- `exz`：例句的中文翻译。
- 中文里不要出现英文或拉丁字母（Dat./Akk. 这类语法缩写只能出现在 `p` 里）。不要编造不常用的义项。

示例：
```json
{"w0123": [
  {"p": "an + Akk. denken", "zh": "想念；想到", "ex": "Ich denke oft an meine Familie in China.", "exz": "我经常想念在中国的家人。"},
  {"p": "über + Akk. denken", "zh": "对……的看法", "ex": "Wie denkst du über das neue Projekt?", "exz": "你觉得这个新项目怎么样？"},
  {"zh": "认为；以为", "ex": "Ich denke, dass wir das bis Freitag schaffen.", "exz": "我觉得我们周五前能完成。"}
]}
```

## 质量
- 例句语法必须正确（格、词尾、动词位置、可分前缀、反身代词）。写完自己再检查一遍。宁可少而准。
- 德国德语，新正字法。

## 写法和自查
分批写：每处理约 100 个骨架词，就把这一批的结果写到 `data/usage_us/usNN.partK.json`（K = 1, 2, …；一个对象，只含这一批收下的词）。开始前先看已有的 part 文件，从缺的批次接着写。每写完一个 part 就在仓库根目录运行：
`py -3.11 -I scripts/usage_check.py data/usage_us/usNN.partK.json`，把 ✗ 全部改掉。
全部写完后合并成 `data/usage_us/usNN.json`（一个对象），再检查一次，没有 ✗ 就删掉 part 文件。
